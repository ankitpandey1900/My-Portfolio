# 24_AGENTS

## Purpose

This document provides coding instructions for AI agents developing, refactoring, or optimizing the **Solar Portfolio** codebase. It acts as an instruction set to ensure code generated by AI align with the project's architectural decisions, directory structures, performance budgets, and coding standards.

## Goals

1. **Prevent Code Regression:** Stop AI agents from introducing code that breaks visual rendering, accessibility guidelines, or SEO systems.
2. **Standardize Code Delivery:** Ensure code generated by AI matches the established TypeScript, React, and Three.js styles.
3. **Optimize Asset Implementations:** Enforce strict file size limits and rendering rules for WebGL performance.

## Architecture

The rules defined in this document are organized into distinct layers: **Core Conventions**, **Canvas vs. HUD Rules**, **Forbidden Practices**, and **Validation Checkpoints**.

## Decisions

### 1. Canvas vs. HUD Decoupling Rule

- **3D Canvas Elements:** Store R3F and Three.js logic in `src/components/canvas/`.
- **2D DOM Overlays:** Store all HTML interface components, panels, forms, and cards in `src/components/hud/` or `src/features/`.
- **Bridge State:** Use the Zustand store (`src/lib/store.ts`) to pass state changes between layers, rather than using direct reference objects.

### 2. Forbidden Practices

AI coding agents are strictly prohibited from implementing the following:

- **No `any` Types:** Do not use `any`. Define explicit interfaces or types for all objects.
- **No Raw GLTF Imports:** Do not import raw uncompressed `.gltf` or `.obj` files. All 3D assets must be Draco-compressed `.glb` files stored in `/public/models/`.
- **No Uncompressed Textures:** Do not import raw PNG/JPG textures. All textures must be compressed to `.ktx2` format and loaded using R3F's KTX2Loader.
- **No Inline Styles:** Do not write inline CSS styles (`style={{...}}`) for HUD overlays. Use Tailwind class names instead.
- **No State Triggers in useFrame:** Do not update React state variables inside R3F `useFrame` loops, as this will trigger re-renders that stall the canvas loop. Modify properties (like position vectors) directly on mesh references instead.

### 3. API & Database Operations

- **Server Actions:** Use Server Actions for form submissions (contact, quotes). Ensure inputs are validated using Zod schemas before running database queries.
- **RLS Policies:** Do not write queries that bypass database Row Level Security. All client-side calls to Supabase must use anonymous client hooks.

## Tradeoffs

- **Auto-Fixing vs. Hard Errors:** Enforcing strict build errors on minor styling issues can slow down development. _Decision:_ Code formatting issues (such as trailing spaces) should be resolved automatically using Prettier scripts, while type errors and RLS violations trigger build errors.

## Future Expansion

- **Self-Improving Agent Rules:** Allow agents to update this document with lessons learned after fixing complex setup bugs.

## Risks

- **Agent Hallucinations:** AI agents can import non-existent libraries or reference incorrect file paths. _Mitigation:_ Ensure agents verify paths against active files in the workspace directory before committing code changes.

## Acceptance Criteria

- Code generated by AI compiles successfully with zero TypeScript, ESLint, or Next.js build errors.
- UI layouts maintain the established design system colors and layout structures.
- 3D rendering updates maintain stable frame rates on standard desktop and mobile profiles.
